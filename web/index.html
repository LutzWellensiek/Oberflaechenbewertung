Ein Datensatz. Für jedes Modell.
Deine Ausschnitte und Bewertungen werden einmal gespeichert und bei jedem Modellwechsel automatisch übernommen. Jedes Modell erhält eine eigene Python-Umgebung, eigene Gewichte und einen eigenen Lernstand. Deine festgelegten Bewertungen bleiben dabei gleich.
Erkannte Testhardware: NVIDIA GTX 1650 Ti · 4 GB VRAM. DINOv2 ist der leichteste Einstieg. Die größeren Modelle standardmäßig auf der CPU testen; das kann langsam sein. Größenangaben unten beziehen sich auf unquantisierte Hugging-Face-Gewichte.
So lernt die Anwendung
85 % Gewicht für die Hauptstufe, 15 % für die Feinabstimmung. Nach jeder Bestätigung wird das ausgewählte Lernmodell im Hintergrund neu trainiert. Beim Wechsel übernimmt das nächste Modell alle gespeicherten Bewertungen automatisch. Bereits aktuelle Lernstände werden sofort wiederverwendet. DINOv2 nutzt vortrainierte Bildmerkmale. Bei den Vision-Sprachmodellen lernt ein zusätzliches Korrekturmodell aus Farb- und Texturmerkmalen; die großen Modellgewichte bleiben unverändert.
Unsicherheit ist eine Heuristik. Die Trefferquote wird aus Vorschlägen vor deiner Bestätigung berechnet; sie ist keine unabhängige Testmessung. Mehr Daten garantieren keine höhere Genauigkeit. Verwende konsistente Kriterien und unterschiedliche Beispiele.

  
Deine Qualitätskriterien
Beschreibe, was eine gute Oberfläche ausmacht. Nutze einheitliche Kriterien für den gesamten Datensatz.
Namensschema: YYYY-MM-DD_HH-MM-SS_Originalname_Score.jpg. Bei Namenskonflikten wird eine laufende Nummer ergänzt.
Lokale Ablage
Die Datenbank, unveränderte Importkopien und Lernstände liegen im Projektordner unter data. Sichere diesen Ordner regelmäßig zusammen mit deinem Ausgabeordner. Für eine konsistente Sicherung die Anwendung vorher schließen.
Gemma benötigt eine freigeschaltete Hugging-Face-Lizenz und einen HF_TOKEN in der lokalen Umgebung vor dem Start. Das Token wird nicht im Projekt gespeichert.
